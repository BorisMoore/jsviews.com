On jsviews.com -
For developing an update, can make changes to a copy (jsviews_CandidateUpdate.js) of download/jsviews.js. 
Then when ready to publish, copy the corresponding changes from the jsviews_CandidateUpdate.js to "_src/jsrender.js", to "_src/jquery.observable.js", and to "_src/jquery.views.js".
(Can use VisualStudio webExtensions diff selected files. Or similar with VSCode.)

Update latest version number (e.g. 1.0.5 -> 1.0.6)
on _src/templates/-version.txt, on contents-download.js (13 instances) and on test.min.mapCDN (4 instances)

Reset left hand nav pane folder hierarchy to standard one, and save categories (using a fresh instance without running search, otherwise you get "loadingfind" ...  "loadedfind")

Make sure no samples have uncommented script blocks which should be commented (e.g. use Search on all .html files. for  "^<script src=.*<!--uncomment"
Recompile the search files, by hitting compile on dash.html (Previously did this with dash.html as start page in VS, but this no longer seems to work now IE has gone away. 
So instead debug dash.html in Chrome) - Then take compiledFindResult properties, and copy from text visualizer (In Chrome go to compiledFindResult properties and copy contents of 
string for each property, then paste into find-xxx.js for each modified top-level category.
(Consider making a Node.js function to call from command line, using phantom, and saving to file system, to avoid this manual copying step...)
Consider checking no truncated .js.map files, by doing a search on all '*.js.map;' files '[^}]$' (with regular expressions) - see https://github.com/BorisMoore/jsviews/issues/445
(and also on jsrender and jsviews projects)

Replace jsrender.js on node_modules jsrender, and jsviews.js, jquery.views.js, jquery.observable.js and jsrender.js on node_modules jsviews,
so browserify picks up latest version
